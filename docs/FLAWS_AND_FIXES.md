# Flaws review — found, fixed, and still-open

Review of the implementation as of WP1 + the WP2/WP3/WP5 (mock-path) vertical slice.

## Fixed in this pass
1. **Mentions could double-count on re-ingestion** (violated idempotency / rule 2).
   → Added `mentions.platform_mention_id` + unique `(politician_id, platform, platform_mention_id)`;
   ingestion skips dupes. Proven by `test_ingest.py::test_ingest_is_idempotent_on_rerun`.
2. **No external-call resilience layer.** → `app/clients/resilient.py` (`resilient_call`) wraps every
   real external call in retry + exponential backoff + graceful default (rule 3).
3. **No token-health surface** (rule 4). → `MetaClient.token_health` + worker writes
   `token_health:{id}` to Redis; the dashboard reads it (no network on read path).
4. **Dashboard had no caching** and risked hitting the DB on every load. → `app/cache.py` Redis
   cache with TTL; degrades to a DB read if Redis is down.
5. **Test-DB URL bug** silently skipped all DB tests (corrupted the username). → fixed with
   `rpartition`. DB tests now actually run.
6. **Spike push dedupe** had no persistence design. → dedupe is the `aggregates.is_spike`
   transition (False→True), crash-safe and idempotent; proven by the crown-jewel test.

## Still open / recommended (by priority)

### High
- **Meta OAuth + live Graph client are now built** (`app/clients/meta.py`, `app/api/auth_meta.py`)
  and unit-tested with mocked HTTP. They need *your* Meta App ID/Secret + a one-time owner login to
  go live (see `docs/CONNECT_INSTAGRAM.md`). Graph field/scope/metric names are marked `# VERIFY`
  and should be confirmed against current Meta docs before production (Meta renames these).
- **Scraper supplement** has a provider-agnostic interface + Fake; the `ApifyScraperClient` is a
  documented stub awaiting a paid key + actor id.
- **Google NL sentiment is now wired** (`app/clients/google_nl.py`, `app/services/nlp.py`): live
  REST client + cost sampling (`NLP_SAMPLE_RATE`) + lexicon fallback, refined scores feed the 40%
  comment component of the aggregate. Set `GOOGLE_NL_API_KEY` + `USE_FAKE_CLIENTS=false` to go live.
- **WP9 done:** topics (multilingual dictionary + LLM extraction), X via SocialData (Fake + real
  stub), Public Voice + Trends modules. **AI Brief (WP11 core) done** via OpenRouter (free-model
  configurable) — generated by the worker, read from cache on the page (no LLM call on read path).
- **WP4/WP6/WP10/WP11 done:** India city map + reach-growth + audience snapshot (WP4); ManyChat DM
  webhook, metadata-only (WP6); geo inference + misinformation claim-volume flag (WP10); ground-input
  form + CSV export (WP11). All 6 modules + ground report + connect are live.
- **Deliberately deferred:** PDF reports (needs a heavy new dep — CSV ships now), admin panel +
  multi-tenant (moot for single-user), real FCM push to a device (WP5 still uses Fake send).
- All external clients run as Fakes under `USE_FAKE_CLIENTS=true`; set provider keys +
  `USE_FAKE_CLIENTS=false` to go live.
- **`detect_spike` baseline uses a flat /168 average.** Fine for demo; a robust version should
  exclude hours with zero data and consider per-hour-of-day seasonality (politicians get more
  comments in the evening). Revisit in WP5 hardening.
- **No auth on the API.** Dashboard endpoints are open. Before multi-tenant (WP11) add auth +
  per-tenant row scoping; today any caller can read any politician id.

### Medium
- **Lexicon is now the fallback, not the primary** — Google NL is wired (WP8). The lexicon still
  handles sampled-out comments and unsupported languages; that's intended cost control, not a flaw.
  Hindi/Marathi sentiment quality depends on Google NL's language support — verify before relying on it.
- **Front-end bundle is ~630 kB** (recharts + d3). Add route-level code-splitting / manualChunks
  before production.
- **`PostMetric` writes a new row every cycle.** Good for time-series, but needs a retention/rollup
  job or the table grows unbounded. Add a pruning task in WP7.
- **IST handling:** stored as timezone-aware UTC-equivalent; verified by tests, but add an explicit
  end-to-end IST assertion in the WP7 integration test.

### Low
- **No Sentry / error tracking** yet (prod-gate item).
- **`docker-compose.yml` not exercised** locally (native dev path); smoke-test before deploy.
- **Frontend has no component tests** (only backend is tested).

## What is intentionally NOT built (per constitution — not flaws)
WhatsApp monitoring, DM *content* reading, ward/pincode geo, free real-time X. These are
documented constraints, surfaced in the UI as honest notes.
